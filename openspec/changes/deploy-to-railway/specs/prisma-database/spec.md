## ADDED Requirements

### Requirement: PostgreSQL via Railway managed database
The system SHALL support connecting to a Railway-provisioned PostgreSQL database via the `DATABASE_URL` environment variable.

#### Scenario: DATABASE_URL from Railway PostgreSQL
- **WHEN** a Railway PostgreSQL service is linked to the app service
- **THEN** `DATABASE_URL` SHALL be automatically injected by Railway

### Requirement: Prisma schema committed to repo
The Prisma schema files (generated by `@siteping/cli init`) SHALL be committed to the repository at `packages/adapter-prisma/prisma/schema.prisma`.

#### Scenario: Prisma schema exists
- **WHEN** the repo is cloned
- **THEN** `packages/adapter-prisma/prisma/schema.prisma` SHALL exist with `SitepingFeedback` and `SitepingAnnotation` models

### Requirement: Auto-migration on deploy
Prisma migrations SHALL run automatically before each deploy as a pre-deploy command.

#### Scenario: Migration runs before deploy
- **WHEN** a new deployment is triggered on Railway
- **THEN** the pre-deploy command SHALL run `prisma db push` or `prisma migrate deploy` before the app starts

### Requirement: In-memory fallback when no database
The system SHALL work without a PostgreSQL database by using the in-memory store adapter (`@siteping/adapter-memory`).

#### Scenario: No DATABASE_URL set
- **WHEN** `DATABASE_URL` is not set
- **THEN** the app SHALL use `@siteping/adapter-memory` and SHALL NOT attempt to connect to PostgreSQL

### Requirement: Prisma Client generation
The build process SHALL generate the Prisma Client during the Docker build.

#### Scenario: Build generates Prisma Client
- **WHEN** Docker builds the image
- **THEN** `prisma generate` SHALL run as part of the build (handled by PostInstall hook in Prisma or explicit step)
